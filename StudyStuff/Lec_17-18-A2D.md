
### Comprehensive Summary of Key Concepts

#### From "Real-Time & Linux" (Slides 17)

1.  **Real-Time Systems Definition**: Systems where jobs must be started and completed by specific deadlines. Key terms are **Job**, **Release Time**, **Response Time**, and **Relative Deadline**.
2.  **Hard vs. Soft Real-Time**:
    *   **Hard Real-Time**: Missing a deadline is a fatal system failure. Requires **guaranteed services** proven mathematically or via exhaustive simulation (e.g., train collision avoidance, airplane flight control).
    *   **Soft Real-Time**: Missing a deadline degrades performance but is not catastrophic. Provides **best-effort services** often validated with statistical analysis (e.g., video stutter).
3.  **Goal of RT Systems**: Achieve **low and deterministic latency**. Non-deterministic latency can cause failures, as in a Battery Management System's over-current shutdown.
4.  **OS Support (Linux RT Patch - PREEMPT_RT)**: The goal is to make the Linux kernel fully preemptible, minimizing non-preemptible code sections to reduce scheduling latency. Many features have been integrated into the mainline kernel.
5.  **Application Requirements for Deterministic Latency**:
    *   **Memory Locking (`mlockall`)**: Prevents pages from being swapped to disk, avoiding non-deterministic delays from **page faults**.
    *   **Stack Memory Management**: Pre-allocate and set stack sizes for threads (`pthread_attr_setstacksize`) to prevent faults when memory is locked.
    *   **Avoid Dynamic Memory** on RT paths: Allocate all required memory during initialization to prevent non-deterministic allocation/freeing during critical operations.
    *   **Priorities and Scheduling**: Use the OS scheduler effectively by assigning appropriate priorities to time-critical tasks.

#### From "FMEA" (Slides 18)

1.  **FMEA (Failure Mode and Effects Analysis)**: A systematic, proactive method for identifying potential failures in a system, their causes and effects, and for prioritizing actions to mitigate them.
2.  **FMEA Process**:
    1.  Identify a component and its **failure mode** (how it fails).
    2.  List the **effects** of that failure.
    3.  Identify **potential causes**.
    4.  Define how the failure is **detected**.
    5.  Rate each of the above on a scale of 1-10 for **Severity (S)**, **Occurrence (O)**, and **Detection (D)**.
    6.  Calculate the **Risk Priority Number (RPN) = S × O × D**.
    7.  Use the RPN to prioritize **recommended actions** to reduce risk.
3.  **Reliability Metrics**:
    *   **MTBF (Mean Time Between Failures)**: The average operational time between inherent failures of a repairable system.
    *   **FIT (Failures in Time)**: The number of failures expected in one billion (10⁹) device-hours.
4.  **Bathtub Curve**: Describes the typical failure rate of a product over time, with three phases: high "infant mortality" failure rate (decreasing), a constant failure rate (useful life), and an increasing "wear-out" failure rate.

#### From "Voltage, A2D, PWL, Noise" (Slides 7)

1.  **Analog Signals & Voltage**: Real-world signals (e.g., from a microphone) are often analog voltages. Systems like BeagleBone use specific DC voltage levels (e.g., 3.3V, 1.8V).
2.  **Analog-to-Digital Conversion (A2D/ADC)**:
    *   Converts a continuous analog voltage to a discrete digital number.
    *   **BeagleBone's 12-bit A2D**: Reads voltages between 0V and 1.8V, outputting values from 0 to 4095.
    *   **Quantization**: The resolution per bit is `Voltage Range / (2^Bits)`. For the BBB, this is 1.8V / 4096 ≈ 0.44 mV.
    *   **Sample Rate**: The speed at which conversions happen (BBB: up to 1.6MHz).
3.  **Piecewise Linear (PWL) Approximation**: A method to approximate complex functions using a series of straight line segments between selected data points. It's computationally cheaper than high-order polynomials.
4.  **Noise**:
    *   Unwanted fluctuations in a signal. `A2D Sample = (true value) + (noise)`.
    *   **Problems**: Can cause erroneous decisions (e.g., falsely reading a battery as dead).
    *   **Mitigation Strategies**:
        *   **Threshold with Consecutive Samples**: Require multiple samples past a threshold before acting.
        *   **Hysteresis**: Uses different thresholds for entering and exiting a state to prevent "chatter" (e.g., enter low-power at 30% battery, exit at 35%).
        *   **Filtering**:
            *   **Simple Moving Average**: Averages the last N samples. Effective but introduces lag.
            *   **Exponential Smoothing**: A recursive filter that applies a weighted average between the current sample and the previous output. Parameter `a` controls responsiveness vs. smoothness.
