### Summary of Key Concepts

#### 1. Node.js Slides (351-1257-10-NodeJS.pdf)

This document covers building web applications with Node.js, from serving static files to creating dynamic, real-time applications.

*   **Static Web Pages:** The foundation of the web. Comprised of:
    *   **HTML (.html):** Defines the structure and content of the page.
    *   **CSS (.css):** Defines the visual style and layout.
    *   **JavaScript (.js):** Adds client-side interactivity within the browser.
*   **Client-Side JavaScript & DOM:** JavaScript runs in the browser and can manipulate the Document Object Model (DOM) - the programming interface for the HTML document. Libraries like **jQuery** simplify DOM manipulation (e.g., selecting elements, changing content, handling events).
*   **Serving Static Content with Node.js:** Node.js can act as a web server. It uses the `http` and `fs` (file system) modules to asynchronously read files from the disk (e.g., from a `/public` directory) and serve them to clients upon request. The `mime` module is used to set the correct `Content-Type` header.
*   **Dynamic Content with WebSocket:** For real-time, bidirectional communication between client and server (e.g., a chat app, live updates). The `socket.io` library is used. The sequence is:
    1.  Client UI (JavaScript) emits an event (e.g., `'daAdd'`) with data to the server.
    2.  Server-side module (e.g., `math_server.js`) listens for the event, processes the data, and emits a response (e.g., `'daAnswer'`).
    3.  Client-side JavaScript listens for the response and updates the DOM.
*   **Node.js to C Program (UDP):** Node.js can integrate with existing C applications using UDP sockets. The Node.js server acts as a relay between the web client (via WebSocket) and the C program (via UDP).
*   **HTTPS:** For secure communication. Requires generating a private key and public certificate and modifying the server to use the `https` module.

#### 2. Electronics Slides (351-1257-11-Electronics.pdf)

This document provides a crash course in basic electronics for interfacing with microcontrollers like the BeagleY-AI.

*   **Units:** Mega (M, 10⁶), Kilo (k, 10³), Milli (m, 10⁻³), Micro (µ, 10⁻⁶).
*   **Ohm's Law:** The fundamental law for circuit analysis: **V = I * R** (Voltage = Current * Resistance).
*   **Key Components:**
    *   **Resistor:** Limits current flow. Not directional.
    *   **Switch:** Opens (infinite resistance) or closes (0 resistance) a circuit.
    *   **LED (Light Emitting Diode):** Emits light when current flows through it in the correct direction (anode to cathode). It has a forward voltage drop (~2V).
*   **Pull-Up/Pull-Down Resistors:** Used with input pins (like GPIOs) to define a known state (HIGH or LOW) when a switch is open. Prevents the pin from "floating."
    *   **Pull-Down:** Resistor connects GPIO to GND. Switch connects GPIO to Vcc. Read `1` when pressed.
    *   **Pull-Up:** Resistor connects GPIO to Vcc. Switch connects GPIO to GND. Read `0` when pressed.
*   **GPIO Limitations:** GPIO pins on the BeagleY-AI are 3.3V tolerant.
    *   **Sourcing:** Providing current from the pin (at 3.3V). Limit is typically **9mA**.
    *   **Sinking:** Allowing current into the pin (at 0V). Limit is typically **5mA**.
*   **Breadboard:** A tool for prototyping circuits without soldering. Key layout: horizontal power rails, vertical connected terminal strips.

#### 3. Bit Twiddling Slides (351-1257-13-BitTwiddling.pdf)

This document covers techniques for manipulating individual bits within a number, crucial for low-level hardware programming.

*   **Bitwise Operators:**
    *   **OR (`|`):** Sets bits. Used to turn bits on. `x |= mask`.
    *   **AND (`&`):** Clears bits. Used to read bits or turn them off. `x &= ~mask`.
    *   **XOR (`^`):** Toggles bits. `x ^= mask`.
    *   **NOT (`~`):** Inverts all bits.
*   **Bit Flags and Masks:** A method of storing multiple boolean values in a single integer variable.
    *   **Flag:** A single bit representing a state (e.g., `LED_ON`).
    *   **Mask:** A value with `1`s in the positions of the bits you care about and `0`s elsewhere (e.g., `LED_MASK = 0xF000`).
*   **Techniques:**
    *   **Check if a bit is set:** `(value & (1 << bit_number)) != 0`
    *   **Set a bit:** `value |= (1 << bit_number)`
    *   **Clear a bit:** `value &= ~(1 << bit_number)`
    *   **Toggle a bit:** `value ^= (1 << bit_number)`
    *   **Read a multi-bit field:** `(value & FIELD_MASK) >> FIELD_OFFSET`
    *   **Write a multi-bit field:** `value = (value & ~FIELD_MASK) | (new_value << FIELD_OFFSET)`
*   **C Bit-Fields:** A language feature to define the number of bits for a struct member (e.g., `unsigned int led : 4;`). While convenient, the bit layout is compiler-dependent and non-portable.
